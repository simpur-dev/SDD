## 1. seekdb（指定组件：存储 + 混合检索）

### 1.1 定位与发布

- seekdb 是 OceanBase 于 **2025-11-18 年度发布会发布并开源（Apache 2.0）** 的"AI 原生混合搜索数据库"，统一管理关系、向量、文本、JSON、GIS，支持多模统一混合检索；官方称"三行代码构建知识库/智能体"。
- 第五届 OceanBase 大赛决赛已使用：赛题包括"全文检索+标量过滤混合查询性能优化（召回率≥0.95）"与"多模态 RAG"。
- 来源：
  - 官方文档（What is seekdb）：https://docs.seekdb.ai/seekdb/seekdb-overview/
  - 发布博客：https://open.oceanbase.com/blog/23633322784
  - 新华网（第五届大赛）：http://www.news.cn/tech/20260118/979133f009904c4f8bfaa5b53f80b991/c.html

### 1.2 部署模式（关键）

| 模式 | 形态 | 平台 |
|---|---|---|
| Embedded | 随 pip 安装、以库形式内嵌（`path="./seekdb.db"`） | **仅 Linux(glibc≥2.28)/macOS；Windows 不支持** |
| Client/Server | 独立服务，**Docker：`docker run -d -p 2881:2881 -p 2886:2886 oceanbase/seekdb`**；2881=SQL，2886=HTTP | 全平台（Windows 用 Docker Desktop） |
| OceanBase | 对接 OceanBase 集群 | 全平台 |

- 备选镜像：`quay.io/oceanbase/seekdb`；也支持 yum/systemd、rpm 包安装。
- 来源：
  - Python SDK 混合检索（明确"Windows only server-mode"）：https://docs.seekdb.ai/seekdb/V1.1.0/using-seekdb-in-python-sdk/
  - Docker 部署（SQL 体验）：https://docs.seekdb.ai/seekdb/experience-vector-search-with-sql/
  - systemd/包管理：https://docs.seekdb.ai/seekdb/deploy-by-systemd/

### 1.3 客户端 pyseekdb

- pip 包：`pyseekdb`（装客户端会附带 embedded seekdb）；单一 API 面支持三种连接。
- 两种 API 风格：
  1. **Collection API（类 Chroma）**：
     - `admin = pyseekdb.AdminClient(path=...)`；`admin.create_database(name)`
     - `client = pyseekdb.Client(path/database 或 host/port/user/password)`
     - `col = client.get_or_create_collection(name)`；`col.add(ids, documents, metadatas)`；`refresh_index()`
     - `col.hybrid_search(query={"where_document":{"$contains":...},"n_results":N}, knn={"query_texts":[...],"n_results":N}, rank={"rrf":{}}, n_results=N)`
  2. **SQL API**：`cursor.execute(...)`；支持 `VECTOR(n)` 类型、`VECTOR INDEX ... WITH (DISTANCE=l2, TYPE=hnsw, LIB=vsag)`、`FULLTEXT INDEX`、堆表 `ORGANIZATION HEAP`。
- Embedding Function 可插拔（OpenAI / 通义千问 / Ollama 等）。
- 来源：
  - https://docs.seekdb.ai/seekdb/V1.1.0/using-seekdb-in-python-sdk/
  - Simple Example：https://docs.seekdb.ai/seekdb/V1.0.0/pyseekdb-simple-sample/
  - PyPI seekdb（SQL 片段）：https://pypi.org/project/seekdb/
  - pyseekdb PyPI：https://pypi.org/project/pyseekdb/1.3.0.dev1/
  - Embedding functions：https://docs.seekdb.ai/seekdb/ef-overview-py/

### 1.4 混合检索 DSL（DBMS_HYBRID_SEARCH）

> **【勘误 2026-09-25 容器实测】** 官方镜像 `oceanbase/seekdb:latest`（=v1.4.0）中 `information_schema.routines` 为空、`CALL DBMS_HYBRID_SEARCH.SEARCH(...)` 返回 1305 不存在、2886 非普通 REST。即该版本**未内置此 SQL 包**；混合检索应通过 pyseekdb 的 `collection.hybrid_search` 完成（见第 7 节）。以下 DSL 为官方文档描述，留作参考。

- 系统包 `DBMS_HYBRID_SEARCH`：`SEARCH(table, json_param)` 返回按相关性排序的 JSON；`GET_SQL` 返回实际 SQL。**仅堆表支持**。
- JSON DSL（ES 风格）：
  - 标量：`query.bool.must/filter` + `term / terms / range(gte,lte)`
  - 全文：`query_string(fields 权重, query, boost)`、`match`
  - 向量：`knn{field,k,query_vector,filter}`，支持**多路 knn（数组）+ size**
  - 融合：`rank.rrf{rank_window_size, rank_constant}`（默认加权混合）
  - 投影：`_source`，结果含 `_score / _keyword_score / _semantic_score`
- 来源：https://docs.seekdb.ai/seekdb/zh-CN/hybrid-search/

## 2. PowerContext（指定组件：记忆 + 上下文接续）

### 2.1 定位与发布

- OceanBase 开源（**Apache 2.0**）的"面向人机协作的上下文运行层"；PyPI 包 **`powercontext` 1.0.0（2026-09-11 发布）**；要求 Python 3.11+；**macOS/Linux 支持，Windows 为 experimental**。
- 是 PowerMem 的继任者；口号"Memory 让事实不被忘记，Handoff 让工作不必重来"。
- 来源：
  - PyPI：https://pypi.org/project/powercontext/
  - 官方技术解析（CSDN）：https://oceanbase.csdn.net/6aab541e8f401d362660d5d0.html
  - 仓库：https://github.com/oceanbase/powercontext

### 2.2 核心概念

| 概念 | 含义 |
|---|---|
| **Source** | 证据来源（代码/文档/工单/trace/Agent 轨迹/人工输入）；捕获一段提示不会让每句话直接成 Memory；保留引用与证据边界 |
| **Memory** | 长期记忆；保留来源；修订(revise)/停用(retire)不抹历史 |
| **Topic Memory** | 按主题聚合的记忆 |
| **PreparedContext** | Runtime 按 Scope + 相关性 + **字节预算（默认 8,000 UTF-8 bytes）** 生成，附 citation；召回失败降级不阻断 |
| **Handoff** | 工作包：目标/范围/已验证/已放弃/环境约束/**待核实**（与已验证同等显眼）/下一步/证据；生命周期 prepare→activate→finalize→commit，支持 continue/acknowledge |
| **Experience / Skill** | 可复用做法，候选→Review→批准后成为不可变资产 |
| **Scope** | 工作范围，决定哪些资料属同一批；连接同一服务≠选中同一 Scope |
| **Profile / Review** | 主体画像与治理评审 |

### 2.3 接口与部署

- 接入方式：**async Python client（PowerContextClient）、HTTP/OpenAPI、Streamable HTTP MCP、in-process Core SDK**。
- Server：`uv tool install "powercontext[cli,server]==1.0.0"`；`powercontext config init`；`powercontext server run`（默认 127.0.0.1:8000）；持久化后端 **sqlite / seekdb / oceanbase**（仓库 `builtin/persistence/`）。
- 记忆能力：Full（自动抽取/Topic，需生成+Embedding API）/ Basic（显式记忆，无需模型 API）。
- Agent 集成（12 个）：**Codex(official)**、Claude Code、DeepSeek Harness、Hermes、Pi、OpenClaw、OpenCode、WorkBuddy、**Bub(evaluation only)**、Pydantic AI、LangChain、LangGraph。
- 22 个中文 Jupyter 教程（前 7 个无需模型/Key）。
- 客户端关键方法（来自仓库源码 `client/client.py`）：
  - Scope：`create_scope/get_scope/resolve_scope_binding/set_default_scope`
  - Source：`capture_content_source/create_source/get_source/create_work_contract`
  - Memory：`remember_memory/search_memory/get_memory_entry/revise_memory_entry/retire_memory_entry/list_memory_entries/list_memory_changes/flush_memory`
  - Context：`prepare_context/query_code`
  - Handoff：`prepare_handoff/activate_handoff/finalize_handoff/commit_handoff/continue_handoff/handoff_current_work/acknowledge_handoff/get_handoff_report`
  - Outcome/复用：`record_task_outcome/propose_experience/propose_skill/approve_artifact_candidate`

### 2.4 官方评测口径（可借鉴）

- LoCoMo（长对话记忆，1,540 计分题）：PowerContext 准确率 90.78%（vs 全量上下文 52.9%），搜索 p95 1.38s（vs 17.12s），单题约 1.65k Token（vs 26k）。
- SWE-bench Pro public v2（731 任务，Codex，gpt-5.6-sol/medium）：OFF 82.35%（602）→ ON 86.73%（634），+4.38pp / +32 任务。
- 来源：https://oceanbase.csdn.net/6aab541e8f401d362660d5d0.html

## 3. GitHub Spec Kit（方法论 / 模板资产来源）

### 3.1 本质判断

- GitHub 开源的 SDD 工具；Python 包 **`specify-cli`（入口命令 `specify`，Typer/Click）**；本质是"**脚手架 CLI + Markdown 模板/Slash 命令 + 约定目录**"，核心流程 **Specify → Plan → Tasks → Implement → Converge**，每阶段产出 Markdown。
- **无运行时数据库 / 无检索引擎 / 无持久记忆服务**；核心价值在人机可读的 Markdown 规格流转 → 故定位为"模板与方法论资产"，而非运行时骨架。
- 来源：
  - 官网：https://github.github.io/spec-kit/
  - GitHub 博客：https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/
  - 仓库（本地克隆）：https://github.com/github/spec-kit

### 3.2 仓库结构要点（本地核对）

- `templates/`：`constitution / spec / plan / tasks / checklist` 模板 + `templates/commands/`（specify/plan/tasks/implement/converge/analyze/clarify/checklist/constitution/taskstoissues）。
- `src/specify_cli/`：`command_init`、`artifacts/`、`integrations/`（含 codex/claude/copilot/cursor_agent/bob 等大量适配）、以及新版 `bundles/extensions/presets/workflows`（workflows 含 if_then/while_loop/fan_out/gate 等编排原语）。
- `.specify/memory/constitution.md`：宪法模板。
- 依赖轻量：typer/click/rich/pyyaml/pathspec/json5，无数据库依赖。

## 6. 对架构产生决定性影响的结论

1. seekdb 在 Windows 必须走 **Server(Docker)** 模式；**混合检索走 pyseekdb `collection.hybrid_search`（v1.4.0 无 DBMS_HYBRID_SEARCH 包，见 1.4 勘误）**，关系图用原生 SQL 表。
2. PowerContext Windows 为 **experimental**，需 Docker/WSL2 预案；其 Memory/Handoff/Scope/PreparedContext 与赛题职责天然对齐，直接作为记忆层。
3. Spec Kit 是**模板资产**而非运行时骨架，避免"换库式改造"的概念错位。
4. Bub 为**疑似官方评测 Agent**，优先保证 MCP 接入并脚本化演示。
5. 官方题包未定项（Agent/版本/参数）通过**标准 MCP + 可配置后端 + 可插拔模型**解耦，不阻塞开发。

## 7. M2 驱动适配器实测结论（2026-09-25，容器实测）

### 7.1 seekdb v1.4.0 + pyseekdb 1.4.0.post1

- 版本：`5.7.25-OceanBase seekdb-v1.4.0.0`；pyseekdb wheel 纯 Python，远程客户端基于 **pymysql**，连 2881、用户 `root@sys`，Windows 免 embedded 二进制。
- 建集合：`cfg=HNSWConfiguration(dimension=D, distance="l2")`；`client.get_or_create_collection(name, configuration=cfg, embedding_function=None)`（**勿用 kwargs 传 dimension，会重复报错**）。
- 写入：`col.add(ids, documents, metadatas, embeddings)`（显式向量）。
- 混合检索：`col.hybrid_search(query={where_document:{$contains},where,n_results}, knn={query_embeddings:[...],where,n_results}, rank={rrf:{}}, n_results, include)`，返回嵌套结果（取 `[0]`）；**collection 默认即支持中文全文，无需手动 ngram**。
- 裸 SQL：默认 FULLTEXT parser 对中文得 0 分，需 `WITH PARSER ngram`；KNN 用 `ORDER BY l2_distance(embedding,%s)` / `cosine_distance`。
- SpecWeaver 落地：**artifacts 走 Collection，relations 走原生表 `sw_relations`（edge_id=sha1(src|kind|dst)[:16]，UNIQUE(src,dst,kind)），neighbors 查边再取点**；同步 SDK 用 `asyncio.to_thread` 包装。

### 7.2 PowerContext master（API 1.1.0，97 路径）

- scope_id 由服务生成（`scp_xxx`），create 不接受指定 id；按确定性 title（`sw:{project}`）幂等解析。
- Memory：`/v1/memory/remember|search|entries/list|get|revise|retire`；每 scope 一个固定 memory artifact（family/artifact_id 均为 `memory`，revision 递增）；中文全文正常，search 自动 fts。
- Handoff：`/v1/work/handoffs/prepare-current` 直接接收 objective/state/next_action/omissions（WorkClaim basis=declared、evidence 可空），返回 PreparedHandoff；`/v1/handoff/commit` 持久化（ref `handoff:handoff:N`）；**`/v1/handoff/continue` 用 `selection=exact` + revision（latest 不可搭配 revision）**。
- **多主体限制（关键）**：`acknowledge` 与带 `handoff_receipt_ref` 的 outcome 属于"互不信任多 Agent"协议，需不同 access principal + work contract；单 principal 下 acknowledge 返回 422/409。**单 Agent 自接续主线 = Memory + prepare-current/commit/continue + outcome 记录在新 source（202）**，不依赖 acknowledge。

### 7.3 MiniMax 推理

- Chat：OpenAI 兼容 `POST {base}/chat/completions`；Embeddings：`POST {base}/embeddings`，body `{model:"embo-01", texts:[...], type:"db"|"query"}`，**向量维度 1536**（config dim 已改 1536）；type 区分建库/查询，不可混用。

### 7.4 M3.4 反向核对与接续（真实后端实测）

- **活动表**：`sw_change_set` / `sw_test_run` 在 seekdb initialize 时建表，`SeekdbActivityLog` record/list 真实可用，与工程 catalog 分离。
- **关键修复（fakes 无法暴露）**：`record_to_artifact` 从 seekdb 重建 `SourceRef` 时漏带 checksum，导致真实后端 `verify_engineering` 的 checksum 核对被静默跳过（InMemory fake 保留完整对象故一直通过）。已令重建的 `SourceRef.checksum = 顶层 checksum`。
- **supersede 引用需归一**：front-matter `supersedes: REQ-01` 必须走 PREFIX-id 归一，否则匹配不到 catalog 中实际的 `REQ-1`，版本替换静默失效。
- **PC handoff 的 `next_action` 是单字段**（非列表）：prepare 只承载首个 next step，其余步骤应放入 `state`；适配器将其映射为长度 1 的 `next_steps`。
- **GetContext 注入 workspace**：每次取上下文即对有 source 的 artifact 做工程 checksum 核对，落实"实际工程状态 > seekdb > PowerContext"。
- **ResumeTask 三方核对**：catalog 全量 artifact 经 `verify_engineering` 对 workspace，产出 `StateMismatch`；**不自动臆改 catalog**，而是在重新生成的上下文里排除过时记录并提示重新 ingest。干净项目实测：基线 4 artifact、制造变更后 resume 经 handoff 恢复目标，正好检出 code/test 2 处 checksum mismatch，最新 bundle 仅保留仍准确的 requirement/design（citations 2，verification 段为空）。
