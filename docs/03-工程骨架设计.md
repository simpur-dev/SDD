> 第六届 OceanBase 数据库大赛・SDD 工程上下文工具赛题
> 版本：v1.0（工程骨架定稿）　最后更新：2026-09-25
> 上游文档：《01 - 架构设计说明书》（逻辑架构）、《02 - 调研纪要》（事实依据）

## 1. 目的：从 "逻辑架构" 到 "可运行工程骨架"

《01》回答了 "系统由哪些层与引擎构成"，本文回答 "**这些能力落到代码仓库里，包 / 模块 / 接口如何划分、依赖如何约束、如何装配与测试**"。

设计目标：让骨架在 M1 结束时即可 `import specweaver`、运行 `specweaver doctor` 完成自检；后续 M2–M6 只在既定边界内 "填肉"，不返工结构。

## 2. 工程设计原则



| 编号 | 原则                          | 落地约束                                                                        |
| -- | --------------------------- | --------------------------------------------------------------------------- |
| P1 | **六边形（端口 - 适配器）**           | 核心域只定义端口（Protocol），不 import 任何后端 / 框架；seekdb、PowerContext 均为可替换适配器          |
| P2 | **依赖方向单向**                  | `driving → application → domain ← driven`；domain 零依赖，application 只依赖 domain |
| P3 | **包内约定统一**（借鉴 PowerContext） | 每个能力包固定 `models / protocols / service / errors / prompts` 分工                |
| P4 | **可测试优先**                   | 端口自带 InMemory fakes；引擎单测不连真后端；真后端走契约 + 集成测试                                 |
| P5 | **可观测内建**                   | 所有用例经统一埋点（耗时 / Token / 调用次数），直接产出 `evidence/usage.csv`                      |
| P6 | **降级不阻断**                   | 无模型 Key 时自动切规则模式（Basic）；后端不可达给出明确错误与重试口径                                    |
| P7 | **单一权威**                    | 事实只由 seekdb / 工程持有，PowerContext 仅存引用 + 版本（见《01》3.3）                         |
| P8 | **src-layout + 显式依赖**       | 代码在 `src/specweaver`；依赖在 pyproject 按 extras 分组，最小安装                         |

### 2.1 依赖规则（可由 linter 强制）



```
domain/        不得 import: application, adapters, fastmcp, fastapi, pyseekdb, httpx

application/   不得 import: adapters（只引用 domain.ports）

adapters/      可以 import: domain, application(仅 driving 入口) 与具体后端 SDK

shared/        横切工具，不被 domain 依赖
```

## 4. 领域层设计（domain/）

纯 Python + Pydantic v2（仅做数据形状，不引入 IO）。

### 4.1 领域模型清单



| 模型              | 类型  | 关键字段                                                                                                                                                                          |
| --------------- | --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Artifact`      | 实体  | id, project\_id, type, module, title, content, version, status, effective\_from/to, applies\_to\_ref, supersedes/superseded\_by, source(SourceRef), checksum, tags, based\_on |
| `Relation`      | 实体  | id, project\_id, src, dst, kind, confidence, evidence                                                                                                                         |
| `Task`          | 实体  | id, project\_id, title, objective, phase, branch, base\_ref, handoff\_rev, created/closed\_at                                                                                 |
| `ChangeSet`     | 实体  | id, task\_id, files\_changed\[FileChange], base/head\_checksum, test\_run\_id                                                                                                 |
| `TestRun`       | 实体  | id, task\_id, command, total/passed/failed/skipped, report\_ref, commit\_ref                                                                                                  |
| `Event`         | 实体  | id, task\_id, phase, action, payload, citations                                                                                                                               |
| `SourceRef`     | 值对象 | uri, locator (行范围), kind, checksum                                                                                                                                            |
| `Citation`      | 值对象 | artifact\_id, version, source(SourceRef), updated\_at                                                                                                                         |
| `Finding`       | 值对象 | kind(conflict/gap/suspect/unverified), severity, message, refs\[Citation], suggestion, needs\_confirmation                                                                    |
| `Budget`        | 值对象 | max\_bytes, max\_items, used\_bytes                                                                                                                                           |
| `ContextBundle` | 聚合  | task, sections\[4], findings, citations, usage, generated\_at                                                                                                                 |

### 4.2 枚举（enums.py）



```
ArtifactType = requirement | design | code | test | rule

LifecycleStatus = draft | active | superseded | deprecated

RelationKind = realizes | refines | covers | constrains | calls | tests | depends\_on | supersedes

TaskPhase = analyzing | in\_progress | verifying | handoff | done | blocked

FindingKind = conflict | gap | suspect | unverified

Severity = info | warning | critical
```

### 4.3 纯领域规则（rules.py，可单测、无 IO）



* `is_currently_effective(artifact, now, ref) -> bool`：状态 / 时间 / 范围三维判断（工程核对维由应用层补）；

* `supersession_closure(artifact, lookup) -> Artifact`：沿 superseded\_by 求最新版本；

* `expected_chain_complete(relations) -> list[Gap]`：requirement→design→code→test 链路完整性；

* `byte_size(text) -> int`：统一 UTF-8 字节口径（与预算一致）。

## 5. 端口设计（domain/ports/）

端口是 `typing.Protocol`（async），定义应用层所需能力，不含实现。

### 5.1 端口清单



| 端口                     | 职责        | 关键方法（签名示意）                                                                                                              |
| ---------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------- |
| `CatalogPort`          | 工程要素读写    | `upsert_artifact(a)`, `get_artifact(id)`, `list_artifacts(filter)`, `upsert_relation(r)`, `neighbors(id, kinds, depth)` |
| `HybridSearchPort`     | 混合检索      | `hybrid_search(query: HybridQuery) -> list[ScoredArtifact]`                                                             |
| `WorkspacePort`        | 工程现场      | `current_ref()`, `changed_files(base..head)`, `read_file(path)`, `exists(symbol/path)`, `checksum(path)`                |
| `TestRunnerPort`       | 测试执行 / 读取 | `run(command) -> TestRun`, `parse_report(uri) -> TestRun`                                                               |
| `MemoryPort`           | 工作记忆      | `remember(entry, citation)`, `search(query)`, `revise(id)`, `retire(id)`                                                |
| `HandoffPort`          | 任务交接      | `prepare/activate/finalize/commit/continue/acknowledge(...)`                                                            |
| `LLMGatewayPort`       | 生成        | `complete(prompt, schema=None) -> (text, Usage)`                                                                        |
| `EmbeddingGatewayPort` | 向量化       | `embed(texts) -> list[vector]`, `dim`                                                                                   |

### 5.2 HybridQuery（检索请求值对象）



```
HybridQuery:

&#x20; project\_id, text(任务/子查询), modules\[], types\[], status, ref,

&#x20; n\_results, use\_keyword=True, use\_semantic=True, scalar\_filters\[]
```

> Catalog 与 HybridSearch 可由同一 seekdb 适配器实现两个端口；Memory 与 Handoff 由同一 powercontext 适配器实现。

## 6. 应用层设计（application/）

### 6.1 用例（usecases/）与 MCP 工具 1:1

每个用例是一个 `__call__(request) -> response` 的对象，经端口交互、经 telemetry 埋点、写 Event。



| 用例               | 调用的引擎 / 端口                                              | 输出                                |
| ---------------- | ------------------------------------------------------- | --------------------------------- |
| `IngestProject`  | ingestion 引擎 + Catalog + Embedding + Memory (注册 Source) | 摄入报告（新增 / 变更 / 建边数）               |
| `GetContext`     | retrieval + validity + assembly + Memory.recall         | **ContextBundle（4 段 + findings）** |
| `RecordDecision` | Memory.remember                                         | 记忆回执                              |
| `ReportProgress` | Handoff/Memory 更新                                       | 进度回执                              |
| `CompleteTask`   | reconcile 引擎 + Catalog + Handoff.outcome                | 回写报告（变更集 / 测试 / 新版本）              |
| `CreateHandoff`  | Handoff.prepare/commit                                  | handoff\_rev                      |
| `ResumeTask`     | Handoff.continue + Workspace 三方核对 + GetContext          | 最新 ContextBundle + 不一致清单          |
| `VerifyState`    | Workspace vs Catalog vs Memory                          | 一致性报告                             |
| `ExplainSource`  | Catalog 回源                                              | 引用链路                              |

### 6.2 编排器（orchestrator.py）

维护 Task 生命周期状态机（《01》8.3），按序调用用例，保证每步：① 校验前置；② 执行；③ 写 Event；④ 失败可回退 / 标记 blocked。不直接写后端，只编排用例。

### 6.3 五引擎内部结构



| 引擎            | 子模块                                                                                | 输入 → 输出                                          |
| ------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------ |
| **Ingestion** | discovery（发现 / 分类）、parsers/（5 类，code 用 Tree-sitter）、graph\_mining（多证据建图）、embedding | 文件集 → `Artifact[] + Relation[]`（含 checksum / 向量） |
| **Retrieval** | planner（LLM 意图→子查询，无 LLM 时规则切词）、hybrid（组装并调用 HybridSearch）、graph\_expand（沿边补链）     | 任务 + Scope → `ScoredArtifact[]`                  |
| **Validity**  | lifecycle（状态机 / 四维有效）、conflict（规则 + 语义）、gap（链路覆盖）、suspect（下游过时）                    | 候选集 → `有效集 + Finding[]`                          |
| **Assembly**  | bundle（四段映射）、budget（字节预算裁剪 / 排序）、render（Markdown + JSON）                           | 有效集 + findings → `ContextBundle`（双格式）            |
| **Reconcile** | diff\_parse、test\_parse、verify（接续三方核对）                                             | diff + 报告 → `ChangeSet + TestRun + 状态修正`         |

引擎以纯函数 / 窄服务为主，接收端口作为依赖（构造注入），便于单测与 fakes。

## 7. 适配器层设计（adapters/）

### 7.1 Driven（被适配器，实现端口）



| 适配器                 | 实现端口                          | 关键实现要点                                                                                                                                                          |
| ------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `seekdb/`           | Catalog + HybridSearch        | `client.py` 用 pyseekdb 以 host/port 连 2881；`ddl.py` 启动时幂等建表（《01》4.2）；`hybrid_adapter` 把 HybridQuery 翻译为 `DBMS_HYBRID_SEARCH` JSON，解析 `_keyword/_semantic/_score` |
| `powercontext/`     | Memory + Handoff              | `client.py` 经 httpx 调 8000 的 OpenAPI（`/v1/...`）；记忆条目只存**引用 + 版本**；handoff 映射 prepare/activate/finalize/commit/continue/acknowledge                              |
| `workspace/`        | Workspace + TestRunner        | git 命令经子进程（带超时）；checksum 用 sha256；测试命令可配置（默认 pytest），报告解析                                                                                                       |
| `inference/minimax` | LLMGateway + EmbeddingGateway | httpx 调 MiniMax；结构化输出走 JSON schema；统计 prompt/completion tokens                                                                                                  |
| `inference/null`    | LLMGateway + EmbeddingGateway | 无 Key 时：LLM 方法降级为规则 / 抛 `InferenceUnavailable`，Embedding 用确定性哈希伪向量（仅本地联调，标注非语义）                                                                                 |

**适配器翻译职责**：把后端原生异常（pymysql/httpx/timeout）统一翻译为 `shared.errors` 中的领域异常，错误码可追溯，不向上泄漏 SDK 类型。

### 7.2 Driving（驱动适配器，对外入口）



* `driving/mcp/`：


  * `server.py` 用 **FastMCP** 构建，`tools.py` 把 10 个工具（《01》9.1）注册为调用对应 usecase 的薄包装，参数 / 返回用 Pydantic schema；

  * `run_stdio.py`（Agent 拉起）与 `run_http.py`（共享服务，挂载到 `/mcp`，与 PowerContext 同形态）；

  * 工具名统一前缀 `sw_`，并在工具描述里写清输入 / 输出与是否只读（对齐 MCP ToolAnnotations）。

* `driving/cli/`：Typer + Rich，命令见《01》9.2；`doctor` 检查：后端连通、建表状态、模型 Key、Agent 配置。

> 说明：PowerContext 用 OpenAPIProvider 自动投影 REST→MCP；SpecWeaver 因工具是面向 Agent 的编排用例，采用 FastMCP 直接注册（更直观、schema 更可控），REST 仅在需要共享服务时由同一 usecase 暴露。两种方式共享 application 层。

## 8. 组装根与依赖注入（shared/di.py）

唯一负责 "new 对象 + 接线" 的位置（Composition Root）。



```
async with SpecWeaverApp.run(settings) as app:

&#x20;   app.mcp            # FastMCP（driving）

&#x20;   app.cli            # Typer

&#x20;   app.usecases       # 用例表

\# 内部：AsyncExitStack 管理 seekdb/powercontext 连接、缓存、telemetry 的生命周期
```

装配顺序：`settings → driven adapters（建连接/建表）→ engines → usecases/orchestrator → driving(mcp/cli)`。

关闭顺序相反，确保 flush telemetry / 提交 handoff。

## 10. 错误模型（shared/errors.py）



| 异常                       | code 前缀     | 含义                                | retriable |
| ------------------------ | ----------- | --------------------------------- | --------- |
| `SWError`（基类）            | SW          | code, message, details, retriable | —         |
| `BackendConnectionError` | SW-BACKEND  | seekdb/powercontext 不可达           | 是         |
| `ArtifactNotFound`       | SW-NOTFOUND | 要素 / 版本不存在                        | 否         |
| `ConflictDetected`       | SW-CONFLICT | 有效约束冲突（需确认）                       | 否         |
| `InvalidRequest`         | SW-INVALID  | 参数 / 前置校验失败                       | 否         |
| `InferenceUnavailable`   | SW-INFER    | 无模型且无法降级                          | 是（配置后）    |
| `StateMismatch`          | SW-MISMATCH | 接续三方核对不一致                         | 否（需处理）    |

driving 层把异常映射为 MCP/CLI 的标准错误响应（JSON-RPC error / 非零退出 + 可读提示）。



***

## 11. 可观测与用量埋点（shared/telemetry.py）



* `Telemetry`：以 trace\_id 串联一次用例，记录 `usecase, duration_ms, llm_calls, tokens(in/out), backend_calls, result/error`；

* 引擎级指标：检索召回数、findings 数、bundle bytes、组装耗时；

* 导出：`telemetry.snapshot()` → `evidence/usage.csv`（对应评分 "调用用量 / 耗时"），并可 `/metrics`（Prometheus 文本）。

## 14. 关键时序（代码级调用链）

**GetContext（核心读路径）**



```
MCP sw\_get\_context

&#x20;→ GetContext usecase (telemetry 开始)

&#x20;  → Retrieval.planner(LLMGateway) 得子查询

&#x20;  → HybridSearch.hybrid\_search(seekdb) 三路召回

&#x20;  → Catalog.neighbors 图扩展

&#x20;  → Validity.lifecycle/conflict/gap/suspect → 有效集 + Findings

&#x20;  → Assembly.budget 裁剪 → bundle/render 出 md+json

&#x20;→ 写 Event，telemetry 结束

&#x20;→ ContextBundle（4段 + findings + citations + usage）
```

**CompleteTask（核心写路径）**



```
sw\_complete\_task(diff, test\_report)

&#x20;→ Reconcile.diff\_parse/test\_parse（Workspace 核对 checksum）

&#x20;→ Catalog 新版本/状态/关联 + ChangeSet + TestRun

&#x20;→ Validity.suspect 标记/解除

&#x20;→ Handoff.record\_outcome / commit（powercontext，仅引用）

&#x20;→ 写 Event + telemetry → 回写报告
```

**Resume（接续核对）**



```
sw\_resume(handoff\_rev)

&#x20;→ Handoff.continue 恢复目标/进度

&#x20;→ Workspace: ref/checksum/符号/真实测试

&#x20;→ 与 Catalog、Memory 三方比对 → StateMismatch 清单（以工程为准修正）

&#x20;→ 重新 Validity + GetContext → 最新 Bundle
```

## 15. 骨架落地步骤与 M1 验收

落地顺序（每层可独立提交）：



1. pyproject + 包目录 + `__init__`（可 `pip install -e`）；

2. `shared`：config/errors/logging/telemetry/di（先打通装配与配置加载）；

3. `domain`：enums/entities/values/rules + ports（Protocol）；

4. `tests/fakes` + 一条 domain 规则单测（验证可测试性）；

5. `adapters/driving`：CLI `doctor` + MCP 空工具列表能启动；

6. （M2 起）driven 适配器与引擎填肉。

**M1 验收标准**



* `pip install -e '.[cli,mcp,dev]'` 成功；`python -c "import specweaver"` 无错；

* `specweaver doctor` 能报告 seekdb/powercontext 连通状态（接 deploy 起的容器）；

## 附录：设计取舍小结



* 选**六边形**而非按技术分层平铺：核心价值（五引擎）可在不依赖 OceanBase 环境下快速单测，后端可替换、可降级，叙事上直接呼应 "工具" 与 "指定组件" 的分工。

* FastMCP 直接注册而非 OpenAPI 自动投影：SpecWeaver 的工具是 Agent 编排用例，schema 与注解需要精控；REST/MCP 仍共享 application 层，不产生双实现。

* PowerContext 仅存引用、seekdb 持有事实：从工程结构上杜绝双写不一致（《01》3.3）。
