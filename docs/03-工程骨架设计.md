## 2. 工程设计原则



| 编号 | 原则                          | 落地约束                                                                        |
| -- | --------------------------- | --------------------------------------------------------------------------- |
| P1 | **六边形（端口 - 适配器）**           | 核心域只定义端口（Protocol），不 import 任何后端 / 框架；seekdb、PowerContext 均为可替换适配器          |
| P2 | **依赖方向单向**                  | `driving → application → domain ← driven`；domain 零依赖，application 只依赖 domain |
| P3 | **包内约定统一**（借鉴 PowerContext） | 每个能力包固定 `models / protocols / service / errors / prompts` 分工                |
| P4 | **可测试优先**                   | 端口自带 InMemory fakes；引擎单测不连真后端；真后端走契约 + 集成测试                                 |
| P5 | **可观测内建**                   | 所有用例经统一埋点（耗时 / Token / 调用次数），直接产出 `evidence/usage.csv`                      |
| P6 | **降级不阻断**                   | 无模型 Key 时自动切规则模式（Basic）；后端不可达给出明确错误（`SWError` 带 code，MCP 侧 `ToolError`、CLI 侧退出码 2/3）+ 可判定的重放语义（`ToolAnnotations` 的 read-only/idempotent 声明）；**自动重试未实现**（直连超时已设上限，重试策略待真实运维需求再定，不留空头承诺）                                    |
| P7 | **单一权威**                    | 事实只由 seekdb / 工程持有，PowerContext 仅存引用 + 版本（见《01》3.3）                         |
| P8 | **src-layout + 显式依赖**       | 代码在 `src/specweaver`；依赖在 pyproject 按 extras 分组，最小安装                         |

### 2.1 依赖规则（可由 linter 强制）



```
domain/        不得 import: application, adapters, fastmcp, fastapi, pyseekdb, httpx

application/   不得 import: adapters（只引用 domain.ports）

adapters/      可以 import: domain, application(仅 driving 入口) 与具体后端 SDK

evaluation/    不得 import: adapters（与 driving 同级的上层消费方：经 shared.di 装配后驱动 application 用例；被 scripts/ 消费，M7）

shared/        横切工具，不被 domain 依赖
```

## 5. 端口设计（domain/ports/）

端口是 `typing.Protocol`（async），定义应用层所需能力，不含实现。

### 5.1 端口清单



| 端口                     | 职责        | 关键方法（签名示意）                                                                                                              |
| ---------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------- |
| `CatalogPort`          | 工程要素读写    | `upsert_artifact(a)`, `get_artifact(project, id)`, `list_artifacts(filter)`, `upsert_relation(r)`, `neighbors(project, id, kinds, depth)`——逻辑 id（如 REQ-1）跨项目会撞，单件读写一律带 project 收窄 |
| `HybridSearchPort`     | 混合检索      | `hybrid_search(query: HybridQuery) -> list[ScoredArtifact]`                                                             |
| `ActivityLogPort`      | 活动留痕      | `record_change_set(cs)`, `record_test_run(tr)`, `list_test_runs(...)`, `list_change_sets(...)`                           |
| `WorkspacePort`        | 工程现场      | `current_ref()`, `changed_files(base..head)`, `read_file(path)`, `exists(symbol/path)`, `checksum(path)`                |
| `TestRunnerPort`       | 测试执行 / 读取 | `run(command) -> TestRun`, `parse_report(uri) -> TestRun`                                                               |
| `MemoryPort`           | 工作记忆      | `resolve_scope(project)`, `remember(entry)`, `search(scope, query)`, `list_entries`, `revise(citation)`, `retire(citation)`                        |
| `HandoffPort`          | 任务交接      | `prepare_current(draft)`, `commit(view)`, `continue_(scope, rev)`, `record_outcome(...)`                                 |
| `LLMGatewayPort`       | 生成        | `complete(prompt, schema=None) -> CompletionResult(text, structured, usage)`                                             |
| `EmbeddingGatewayPort` | 向量化       | `embed(texts) -> list[vector]`, `dim`                                                                                   |

> 修订：`HandoffPort.acknowledge` 已删除——实测属"互不信任多 Agent"安全协议，单 principal 返回 422/409（见《02》7.2），本项目单 Agent 自接续不依赖它。
> 修订（M4 批 1）：`MemoryPort.resolve_scope(project)` 新增——PowerContext 实现按确定性 title `sw:{project}` 调 `ensure_scope`，运行期由 driving 层（`app.ensure_scope`）在用例需要记忆/交接且 scope 为空时惰性解析；`ActivityLogPort.list_test_runs` 已由 `GetContext` 消费（最近 TestRun 进 Bundle）。
> 修订（M5）：`MemoryPort.revise/retire/list_entries` 由 `RecordDecision` 消费（改判/停用/按 id 定位条目），`ActivityLogPort.list_change_sets` 与 `TestRunnerPort.parse_report` 由 `VerifyState` 消费（变更集是否落后于工作区、junit 报告与记录结果对账）——预留接口全部落地，无需回删。官方契约补充（对照 powercontext RFC 0014 记忆层设计与本地 OpenAPI 复核）：`remember` 的**相同文本是官方 no-op 语义**（响应 `entry: null`、memory revision 不推进，且 `RememberMemoryRequest` 为 `additionalProperties:false`，无幂等键字段），故适配器按 `entries/list` 回读既有条目以实现幂等；`revise` 不参与该去重，但必须携带 `entries/list` 取回的最新 citation（陈旧 revision → 409 revision_conflict）。

### 5.2 HybridQuery（检索请求值对象）



```
HybridQuery:

&#x20; project\_id, text(任务/子查询), modules\[], types\[], status, ref,

&#x20; n\_results, use\_keyword=True, use\_semantic=True, scalar\_filters\[]
```

> Catalog 与 HybridSearch 可由同一 seekdb 适配器实现两个端口；Memory 与 Handoff 由同一 powercontext 适配器实现。

## 6. 应用层设计（application/）

### 6.1 用例（usecases/）与 MCP 工具 1:1

每个用例是一个 `__call__(request) -> response` 的对象（统一 `XxxRequest/XxxReport(BaseModel)` 约定），经端口交互、经 telemetry 埋点；活动留痕由 ChangeSet/TestRun 承载。`scope_id` 在用例请求中默认可选（""），需要写记忆/接续交接时由 driving 层经 `app.ensure_scope` 解析后传入；用例直接调用时若 scope 为空则跳过对应记忆动作（`source_registered=false`），不臆写。

> 修订（M4 批 4）：`CompleteTask` 回写时同步**重采关系边**——对变更文件复用 `mine_relations`，未变更的 catalog 构件仅作边上下文（其存量 `based_on` 重发同一确定性边，upsert 幂等、不删边）。此前只换构件不重建边，新需求（REQ-6）的 code/test 层边缺失会产出假缺口（railway 演示实测）。

> 修订（M4 批 6 边界审计）：①适配器翻译契约补齐——`SeekdbClient.run_op` 统一包装全部后端调用、PowerContext 响应字段经 `require()` 读取、`decode_ref` 校验 rev，畸形响应/路径一律 `SWError`（MCP `ToolError`、CLI 打印 + 退出码 2/3），不再泄漏 ValueError/KeyError/AttributeError/OSError；②`git diff` 加 `--relative` 且全局 `core.quotepath=off`，workspace.root 为 git 子目录时回写路径与 ls-files/read_file 同基准（此前嵌套工作区回写整条路径失效）；③空任务文本在检索引擎层短路，不再触达 pyseekdb（其空 `$contains` 会抛 1210）；④`CompleteTask` 以 `total>0` 为通过红线（"没跑测试"不算绿）；⑤`IngestionEngine` 上报 `duplicate_ids`，`IngestProject` 对源文件已消失的存量构件打 `deprecated` tombstone；⑥`mine_relations` 跳过自引用（文件引用自身 id 不成边）；⑦`SuspectDetector` 上报悬空引用（based_on 指向不在 catalog 的上游）；⑧`applies_to_ref` 改整段匹配（`1.2` 不再误配 `release/1.20`）；⑨Assembly 输出件剥离 embedding（render_json/证据体积缩 ~16 倍）且超预算时显式披露；⑩`ResumeReport.handoff_error` 透出接续失败原因（仅捕获 `SWError`，未知异常照崩）；⑪`list_artifacts` offset 分页替代 1000 静默截断；⑫md 解析容忍 UTF-8 BOM、id 引用上限 6 位、`cs-`/`tr-` id 加随机后缀防同毫秒撞键。审计证据：`tests/unit/boundary/` + `tests/integration/test_boundary_live.py`（原 12 处 strict-xfail 全部翻正）。

> 修订（M6 批 c，健壮性收口）：① `CatalogPort.get_artifacts(project, ids)` 新增，用官方 `Collection.get(ids=[...])` 一次取多条，`ExplainSource` 的 upstream BFS 改为按层批量解析（消除自造 N+1）；② `SubprocessTestRunner._parse_junit` 对缺文件与坏 XML 一律翻译成 `SWError`（§7.1 契约），并新增 `tests/unit/test_test_runner.py` 覆盖解析与对账；③ seekdb 侧超时：自建的 pymysql 引导连接带 `connect/read/write_timeout`，而**长生命周期的 `pyseekdb.RemoteServerClient` 不暴露任何读超时**，故每个后端操作由 `client.run_op` 用 `OP_TIMEOUT_SECONDS`（默认 60s）为 await 设界，容器被 WSL 回收时超时翻译成 `SWError` 而不是永久挂死（`tests/unit/test_seekdb_run_op.py` 钉住两条路径）；④ 删除 `SWError` 上无消费者的 `retriable` / `details` 死字段（重试策略未实现，就不留无法兑现的承诺）；⑤ `scripts/gate.py` 以 `-rs` 让 skip 现形，`--live` 下任何跳过判为失败，杜绝把「真后端已验证」误读成空绿；⑥ `GetContext` 回读 PowerContext 记忆注入 Bundle ④段（`MemoryPort.search` 至此有了生产消费者）。

### 6.2 编排器——不自建（生命周期由外部 Agent 承担）

《01》8.3 的 Task 生命周期状态机在交付形态中由**开发 Agent 自身编排**（Agent 依次调用 get_context → 改码 → complete_task / handoff → resume），SpecWeaver 不再自建 orchestrator，避免与 Agent 的循环重复。下表用例即编排点的原子能力；若后续需要无人值守评测，可在 scripts/ 以脚本串联，不进入 application 层。

### 6.3 五引擎内部结构



| 引擎            | 子模块                                                                                | 输入 → 输出                                          |
| ------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------ |
| **Ingestion** | discovery（发现 / 分类）、profiles（仓库档案，§6.4）、parsers/（Markdown 规格 / 标准库 ast 提取 code 与 test / openspec 方言 / Tier-2 文本符号）、graph\_mining（多证据建图）、embedding | 文件集 → `Artifact[] + Relation[]`（含 checksum / 向量） |
| **Retrieval** | planner（LLM 意图→子查询，无 LLM 时规则切词）、hybrid（组装并调用 HybridSearch）、graph\_expand（沿边补链）     | 任务 + Scope → `ScoredArtifact[]`                  |
| **Validity**  | lifecycle（状态机 / 四维有效）、conflict（规则 + 语义）、gap（链路覆盖）、suspect（下游过时）                    | 候选集 → `有效集 + Finding[]`                          |
| **Assembly**  | bundle（四段映射）、budget（字节预算裁剪 / 排序）、render（Markdown + JSON）                           | 有效集 + findings → `ContextBundle`（双格式）            |
| **Reconcile** | diff\_parse、test\_parse、verify（接续三方核对）                                             | diff + 报告 → `ChangeSet + TestRun + 状态修正`         |

引擎以纯函数 / 窄服务为主，接收端口作为依赖（构造注入），便于单测与 fakes。

### 6.4 仓库档案（ingestion profiles，✅ 已交付 2026-10-21）

把"仓库布局 / 格式差异"隔离为**纯策略层**（《01》§5.5），Artifact 元模型与下游引擎零改动。落地与规划的差异以本节为准：

- `ingestion/profiles.py`：`RepositoryProfile`（name + 嗅探前缀 + registry + discovery）+ `resolve_profile(workspace, requested, configured)`——**请求入参 > `WORKSPACE__PROFILE` > 布局嗅探**（嗅探按注册序，`openspec/` 前缀 → openspec，否则默认 specweaver）；未知名抛 `InvalidRequest`（SW-INVALID，列出可选集）；
- 内置三档：`specweaver`（现行模板，默认行为逐字节不变）/ `openspec`（`### Requirement:` 按条目拍平 + 变更 delta → draft/supersedes 版本链，映射表见《01》§5.5.2）/ `plain`（= specweaver 分派 + 非 Python 代码走 Tier-2）；
- `parsers/` 新增两模块：`openspec.py`（Spec/Delta 两解析器 + `classify_openspec` 路径裁决 + `OpenSpecFileDiscovery`——openspec/ 前缀内该裁决是**终审**，None 即跳过，绝不回退通用启发式，这是 archive delta 被排除的机制保证）与 `text_symbols.py`（Tier-2 正则符号：function/class/interface/const 箭头/it·test 用例名/import stem；**不引入 tree-sitter**）；
- 需求粒度 id：`REQ-` + sha1(`capability|requirement名`) 前 12 位（确定性）；delta 条目加盐 change id，draft 永不与 active 撞 id，MODIFIED/REMOVED 的 `supersedes` 指向 active id（依赖批 1 的解析器协议 `parse -> list[ParsedDocument]` 与 normalize 对 hex 形态 id 的透传，二者均已落地）；
- **不新增端口**：文件读写仍经 `WorkspacePort`、写入仍经 `CatalogPort`——六边形边界与契约测试面均未扩大；
- 配置入口：`WORKSPACE__PROFILE`（auto | specweaver | openspec | plain，默认 auto，§9）；`sw_ingest_project` 与 `ingest --profile` 可逐次覆盖（工具总数仍 11），`IngestProjectReport.profile` 回填实际生效档案；
- 局限（如实）：RENAMED delta 段 v1 未建模（跳过）；条目级增量以文件 checksum 为粒度（同文件任一条目变更，整文件条目重嵌入）。

### 7.2 Driving（驱动适配器，对外入口）



* `driving/mcp/`：


  * `server.py` 提供 `build_mcp(app)`：由装配根在构造 `SpecWeaverApp` 之后调用，把已交付的 11 个工具（`sw_ping`/`sw_doctor`/`sw_ingest_project`/`sw_get_context`/`sw_complete_task`/`sw_handoff`/`sw_resume_task` + M5 的 `sw_record_decision`/`sw_report_progress`/`sw_verify`/`sw_explain_source`，《01》9.1）注册为用例的薄包装，`SWError` 统一映射为 MCP `ToolError`（`[SW-xxx] code+message` 可追溯）；scope 解析也收敛到包装层 `_scope()`，与用例调用共用同一错误契约；唯一例外是 `sw_verify`——它是诊断工具，scope 解析失败时降级为"跳过记忆核对"并把原因写入 `notes`，工作区/目录侧核对照常完成；

  * `run_stdio.py`（Agent 拉起）与 `run_http.py`（共享服务，streamable-http 挂 `/mcp`）均经 `async with di.run()` 进入：装配根是唯一构造点，MCP 生命周期内持有 seekdb/PowerContext 连接；`run_http` 另以 `with_metrics_route()` 在既有 Starlette 路由表头部插入 `GET /metrics`（Prometheus 文本），刻意不重建 app 以免破坏 FastMCP 会话管理器的 lifespan；

  * 工具名统一前缀 `sw_`；每个工具都带 MCP `ToolAnnotations`（`readOnlyHint` / `destructiveHint` / `idempotentHint`，实现见 `server.py` 的 `_READ_ONLY` / `_WRITE_IDEMPOTENT` / `_WRITE` 三组常量），Agent 据此判断能否安全重试：读侧 5 个（`sw_ping`/`sw_doctor`/`sw_get_context`/`sw_verify`/`sw_explain_source`）声明只读幂等，`sw_ingest_project` 声明"写但可重放收敛"（upsert + PowerContext 幂等语义），其余 5 个会追加新证据行或新 revision，故 `idempotentHint=False`；全部工具 `destructiveHint=False`（无删除语义，停用只打 tombstone）。

* `driving/cli/`：Typer + Rich，命令见《01》9.2（M4 批 2/3 已交付 `ingest`/`context`/`finish`/`handoff`/`resume` 五个业务命令）；均经 `di.run()` 全装配执行同一批用例，`scope_id` 解析规则与 MCP 一致；公共选项 `--json`（机器可读输出，`context --json` 直接输出 `render_json(bundle)`）与 `--usage-out <path>`（导出 Telemetry 跨度 CSV）；`finish` 测试失败时退出码 1；`doctor` 复用唯一实现 `SpecWeaverApp.doctor()`（后端连通 + 建表引导 + 推理模式/bootstrap 告警）。

> 说明：PowerContext 用 OpenAPIProvider 自动投影 REST→MCP；SpecWeaver 因工具是面向 Agent 的编排用例，采用 FastMCP 直接注册（更直观、schema 更可控），REST 仅在需要共享服务时由同一 usecase 暴露。两种方式共享 application 层。

> 与**官方 seekdb MCP Server** 的边界（评委常见疑问，口径固定在此）：官方那套（`uvx seekdb-mcp-server`，工具含 `execute_sql`/`hybrid_search`/`full_text_search`/seekdb 自带 memory 函数）暴露的是**数据库运维面**——让 Agent 直接写 SQL、查库。SpecWeaver 暴露的是**工程上下文语义面**：Agent 只需要"这个任务当前有效的最小充分依据 + 为什么可信 + 下一棒怎么接"，不该持有 SQL 与库内 schema 知识；SDD 的版本状态机、约束保底、预算裁剪、三方一致性都在 application 层固化，交给裸 SQL 就等于把正确性推给模型。赛题同时要求 seekdb 与 PowerContext 两个组件，官方 seekdb MCP 也不提供 PowerContext 侧的 memory/handoff，因此自建 MCP 是必要条件而非重复造轮；两者可并存（Agent 亦可同时挂官方 seekdb MCP 做临时排查），SpecWeaver 从不假设独占。

## 15. 骨架落地步骤与 M1 验收

落地顺序（每层可独立提交）：



1. pyproject + 包目录 + `__init__`（可 `pip install -e`）；

2. `shared`：config/errors/telemetry/di（先打通装配与配置加载）；

3. `domain`：enums/entities/values/rules + ports（Protocol）；

4. `tests/fakes` + 一条 domain 规则单测（验证可测试性）；

5. `adapters/driving`：CLI `doctor` + MCP 空工具列表能启动；

6. （M2 起）driven 适配器与引擎填肉。

**M1 验收标准**



* `pip install -e '.[cli,mcp,dev]'` 成功；`python -c "import specweaver"` 无错；

* `specweaver doctor` 能报告 seekdb/powercontext 连通状态（接 deploy 起的容器）；

* MCP server 可启动（stdio/http），工具目录可被列出；

* 至少 1 条 domain 单测通过；`tests/unit/boundary/` 是**行为契约**审计回归组（读路径承诺、异常契约、排除项可见性等，逐条对应一个真实缺陷），**不检查 import 方向**——import-linter 未引入，ruff 只做 E/F/I/UP/B 风格与 bug 检查，依赖方向目前靠人工评审与 §2.1 约定维持。

## 16. 评测契约包 evaluation/

v0.4 提交产物要求"统一格式的结构化评测产物"、§2.3 要求"各层独立可启动的初始快照"。骨架落点为一个**顶层第五模块**（与 domain/application/adapters/shared 并列）：

```
src/specweaver/evaluation/
├─ __init__.py
├─ taskpack.py     # ✅ 已交付（990a127）：TaskPack schema v1（pydantic，extra=forbid）
│                  #   + load_pack/load_dir（错误翻译为 InvalidRequest，含文件与字段名）
│                  #   + materialize（ExecutionPlan：project/scope/workspace 隔离派生）。
│                  #   纯函数零 IO；commit 存在性等环境核对在消费脚本
│                  #   （scripts/taskpack_check.py 已交付，run_eval.py 规划）
└─ artifact.py     # EvalRun schema v1（区块见《01》§11.2）+ emit()：从 Telemetry CSV 与
                   # evidence 文件聚合为单份 JSON（M7 规划，下一项）
```

**依赖与边界**：

- import 方向：`evaluation → application + shared`（§2.1）——它经 `shared.di.run()` 装配出 app 后驱动用例，地位等同 driving 层的上层消费方，但**不注册 MCP 工具、不加 CLI 命令**（评测入口只有 `scripts/run_eval.py`，避免运行时面膨胀）；
- 零新第三方依赖（pydantic 已在 core）；TaskPack 清单资产放 `specweaver/taskpacks/*.json`（与 `templates/` 同级的非代码资产，随仓库交付）；
- 版本纪律：两个 schema 都带 `schema_version`，字段只增不改语义；官方统一格式发布后只改 `artifact.py` 的导出映射（《01》附录 A 第 5 项）；
- 测试：§12 已列三个离线测试文件；EvalRun 聚合器对"证据文件缺失"的行为是**显式失败**（不产出半份 JSON），与 P6"不静默降级"一致。

## 附录：设计取舍小结



* 选**六边形**而非按技术分层平铺：核心价值（五引擎）可在不依赖 OceanBase 环境下快速单测，后端可替换、可降级，叙事上直接呼应 "工具" 与 "指定组件" 的分工。

* FastMCP 直接注册而非 OpenAPI 自动投影：SpecWeaver 的工具是 Agent 编排用例，schema 与注解需要精控；REST/MCP 仍共享 application 层，不产生双实现。

* PowerContext 仅存引用、seekdb 持有事实：从工程结构上杜绝双写不一致（《01》3.3）。
