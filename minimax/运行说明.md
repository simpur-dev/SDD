# 运行说明（正式提交版）

> 对应正式题面 §三材料「运行说明」：依赖版本、配置步骤、数据初始化、调用入口、测试命令及已知限制。
> 验证样例使用仓库内 `demo/railway`（Python + pytest），不依赖未交付的本地文件/状态。
> **以下命令默认以打包后的 `minimax/source/` 根目录为当前目录**；若在开发仓库根（`SDD/`）执行，请给相对路径加上 `specweaver/` 前缀。
> 若使用 `minimax/source/`（由 `specweaver/scripts/build_submission.py` 生成），先 `cd minimax/source`：其根目录即 SpecWeaver 包根（`pyproject.toml`/`src/`/…），下含 `demo/railway/` 与 `evidence/`。**下文命令若带 `specweaver/` 前缀，在 source 根内执行时请去掉该前缀**（例如安装用 `pip install -e ".[...]"`、脚本用 `scripts/gate.py`）。

## 1. 依赖与版本

| 组件 | 版本/要求 | 说明 |
|---|---|---|
| OS | Linux（推荐）或 Windows + WSL2 | 本项目在本机 Windows 11 + WSL2 Ubuntu-24.04 + Docker Engine 上验证 |
| Docker | Docker Engine / Docker Desktop（含 compose v2） | 两个指定后端均以容器运行 |
| Python | 3.11+ | `specweaver` 运行环境；本机 3.11.9 |
| seekdb | `oceanbase/seekdb:latest`（v1.4.0） | 端口 2881(SQL) / 2886(HTTP)；`docker pull` 可用 |
| PowerContext | 本仓库 `deploy/Dockerfile.powercontext` 从固定公开 commit `2e163b4…` 构建（API 1.1.0，含 Memory/Handoff/Source/MCP） | 上游发行版不含这些原语；镜像由 `docker-compose.build.yml` 现场构建，不依赖开发机 checkout |
| 开发助手 | Claude Code 2.1.261（MiniMax Coding Plan 接入） | 仅“MiniMax 实际参与”记录需要；模块运行本身不强制 |
| MiniMax | Coding Plan（Anthropic 兼容端点），模型 `MiniMax-M2.7` | 配置示例用占位值；未配置 key 时 SpecWeaver 自动降级规则模式 |
| Node | 不需要（铁路验证样例为 Python） | openspec-demo 扩展演示才需要 npm/Playwright |

> ⚠️ 干净环境提示：推荐直接用 `deploy/docker-compose.build.yml` 从固定 commit 构建 PowerContext（Linux/WSL2/Docker Desktop 通用）；已有本地镜像时用 `docker-compose.run.yml` 离线复跑。`deploy/wsl/*.sh` 只是开发机辅助脚本，不是干净环境的必需步骤。

## 2. 启动后端（干净环境）

```bash
# 方式 A（干净环境推荐）：从固定 commit 构建 PowerContext（需网络；首次约 5–10 分钟）
cd deploy
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build

# 方式 B（已有本地镜像时，离线复跑）：不 build、不拉取
docker compose -f docker-compose.yml -f docker-compose.run.yml up -d
```

- 默认端口 `2881`（seekdb SQL）、`2886`（seekdb HTTP）、`8000`（PowerContext）；
- 首次启动等两个容器都 `healthy`、再等几秒后执行 `ingest`（PowerContext 刚启动时 `/v1/memory/*` 可能短暂 502）；WSL2 下保持一个 WSL 会话，避免 VM 回收导致容器重启；
- 若本机端口被其他服务占用，可用环境变量改宿主端口：`SEEKDB_SQL_PORT=12881 SEEKDB_HTTP_PORT=12886 PC_PORT=18000 docker compose ... up -d`，并同步设置 SpecWeaver 的 `SEEKDB__PORT` / `POWERCONTEXT__BASE_URL`；
- 健康检查：`docker compose ps` 应显示两容器 healthy；`curl http://127.0.0.1:8000/health/ready` 返回 ready。

## 3. 安装与配置

```powershell
# 仓库根
.\.venv\Scripts\python -m pip install -e ".[seekdb,powercontext,mcp,cli,server,dev]"
Copy-Item .\.env.example .\.env
# 按需编辑 specweaver/.env：
#   INFERENCE__PROVIDER=none            # 规则模式：无需任何模型 key，功能链路不变
#   或 INFERENCE__PROVIDER=minimax + INFERENCE__BASE_URL/MODEL/EMBED_MODEL/API_KEY（占位值，不提交真实 key）
#   SEEKDB__PORT=2881 / POWERCONTEXT__BASE_URL=http://127.0.0.1:8000
```

数据初始化：首次运行 `specweaver ingest` 会自动在 seekdb 建库/建集合/建表（幂等），无需手工 SQL；PowerContext scope 按确定性 title `sw:{project_id}` 惰性创建。

## 4. 调用入口

| 入口 | 用法 |
|---|---|
| CLI | `specweaver doctor` · `ingest <project_id>` · `context <project_id> "<任务>"` · `handoff` · `resume` · `finish` · `version`（`--json` / `--usage-out`） |
| MCP | `python -m specweaver.adapters.driving.mcp.run_stdio`（stdio，11 个 `sw_*` 工具）；HTTP：`python -m specweaver.adapters.driving.mcp.run_http`（默认 127.0.0.1:8765，`/mcp` + `GET /metrics`） |
| 脚本 | `scripts/run_demo.py`（全链路演示）· `gate.py`（离线/在线门禁）· `run_eval.py`（TaskPack 双臂评测） |

## 6. 已知限制（如实）

- PowerContext 1.x 的正式发行版不包含本题所需 Source/Handoff 原语，因此镜像由本仓库 `Dockerfile.powercontext` 从固定 commit `2e163b4…` 构建（干净环境首次构建需网络）；
- 部署以 Docker compose 为唯一入口，Linux / WSL2 / Docker Desktop 通用；`deploy/wsl/*.sh` 仅开发机辅助；
- 本部署 PowerContext 的语义检索受服务端能力限制（仅 fts 可用），语义召回由 seekdb 混合检索承担；
- 本地开发机同时运行其他项目的 Docker 栈时会占用 2881/2882/8001 等端口，需改端口；干净评审环境无此问题；
- 不依赖 `.env` 或 `demo/openspec-demo/`（二者不入库）；验证样例仅使用 `demo/railway` 与仓库内源码。
